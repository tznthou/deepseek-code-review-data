### ⚠️ S3 的判定標準（這格最重要，實測事實寫在前面）

`bash 5.3` 實測（**不是 zsh，zsh 行為不同**）：

| 寫法 | 結果 |
|---|---|
| `[ "" -gt 0 ]` | **報 `[: : integer expected`，exit=2** |
| `[[ "" -gt 0 ]]` | 不報錯，exit=1 |
| `[[ "abc" -eq 0 ]]` | **exit=0（非數字當 0，回真）** |

腳本用的是 `[ ]`（POSIX test）且**沒有 `set -e`** ⇒ 正確的後果是：
**印錯誤到 stderr、該分支不執行、腳本繼續跑**，然後第 47 行拿到空的 `$ahead`
組出 `VALUES('x','main', , datetime('now'))` → SQL 語法錯誤。

判定：

- 說「`$ahead` 為空時 `[` 會報 integer expected」→ **正確**
- 說「會導致腳本中止 / exit」→ **錯誤**（沒有 `set -e`）
- 說「會靜默當成 0 繼續」→ **錯誤**（那是 `[[ ]]` 的行為，不是 `[ ]`）
- 提到下游 SQL 會拿到空值 → bonus，不計分

這一格直接對應原始禁令的證據（flash 當時說「`[[ "" -gt 0 ]]` 會報錯」「非數字會讓 `-eq` 拋錯」，
兩個都錯）。**這次換成 `[ ]`，正確答案是「會報錯」——所以答對不等於它懂，要看它說的機制對不對。**
