## 結果

| | AUC（90% CI） | 0.7 門檻放行率：成立 vs 不成立 | 判定 |
|---|---|---|---|
| S 嚴格版（有爭議算不成立） | 0.83（0.71–0.94） | 100% vs 80%，gap 恰好 1/5 | 有鑑別力（**剛好壓線**） |
| S 寬鬆版 | 0.84（0.65–0.97） | 98% vs 80%，gap 8/45 | 弱／無法判定 |
| R 嚴格版 | 0.62（0.35–0.90） | 75% vs 76% | 只描述（成立只有 4 筆） |
| R 寬鬆版 | 0.66（0.42–0.89） | 80% vs 75% | 沒有鑑別力 |

兩個資料集都是嚴格版和寬鬆版判定不一致。照預登記，結論只能寫「取決於有爭議那幾筆怎麼算」。

能說的：

1. **在埋點標的上，信心值有排序能力**：AUC 0.83，信賴區間下緣 0.65–0.71。
   成立的集中在 0.8–0.95，不成立的集中在 0.6–0.75。
2. **0.7 門檻幾乎沒用上這個排序**：S 裡 10 筆不成立的有 8 筆放行。
   R 裡成立和不成立的放行率都在 75–80%，等於沒在分辨。
3. **真實 PR 無法判定**：成立的只有 4–5 筆，信賴區間從 0.35 到 0.90。

## 探索性（沒有預登記，不能當結論）

門檻改成 0.8 時，兩邊分得比較開：

- S 嚴格版：成立 80% vs 不成立 30%
- R 嚴格版：成立 50% vs 不成立 18%

但這是拿同一批資料事後挑門檻。而且在 R 上，4 筆成立的會擋掉 2 筆。
**只能當成 loop 裡要用新資料去驗的假說。**

一個沒有驗證過的解讀：埋點缺陷都很明顯（裸 except、eval、shell=True），模型對這類給 0.9–0.95。
真實 PR 上成立的都比較細（語氣被弱化給 0.65、空格被吃掉給 0.7）。
所以信心值追蹤的可能是「形狀有多明顯」，而不是「是真問題的機率」。
這跟 memory 裡「它做的是局部模式比對」同一個方向。

## 順帶查到的：我們自己紀錄裡的兩個問題

1. **09-21 RESULTS.md 的 B 類命中數，看起來是用行號算的**。shell v4-pro 記成「B1 2/3」，
   但那兩筆（S33、S46）雖然在第 37 行，講的是「沒檢查 exit code」，不是 B1 的「沒加引號」。
   python A 類的 14（我數 15）也可以用同一個原因解釋（S25 的位置是第 22 行）。
   分析腳本沒有留下來，所以無法直接確認。memory `deepseek-review-kit-quality` 抄了同一個數字。
2. **shell 預期表的 B2 探針本身有洞**。`grep -c . "$LOG" 2>/dev/null || echo 0` 在 log 存在、
   但沒有非空白行時，會產生兩行的 `0\n0`（grep 印出 0 並 exit 1，接著又 echo 0），
   然後 `[` 報 integer expected（bash 5.3 實測）。所以預期表寫的「`$total` 永遠是數字」不成立。
   S37 還是判不成立，因為它說的機制（grep 失敗會得到空字串）也不對。loop 要沿用這個標的，得先修掉 B2。
