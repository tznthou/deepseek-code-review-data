## Metric（L2 量化）

- **主 metric**：三個標的合併的 AUC，嚴格版（有爭議算不成立）
  - AUC = P(成立的信心 > 不成立的信心) + 0.5 × P(相等)
- 每一輪：3 個標的 × 5 次，`deepseek-v4-pro`，參數照 CI（`scripts/run_round.py`）
- **keep**：主 metric ≥ 目前最佳 + 0.05，anti-criteria 全過，Guard 通過
- **達標**（提早停；baseline 就達標則不開 loop）：主 metric ≥ 0.90
- **爆衝**：單輪 +0.10 以上 → 先請子超從該輪盲抽 10 筆標記複核，差異太大就停 loop 改 metric

## Anti-criteria（違反任一條 → discard，不看分數）

- **a**：15 次跑全部產出可解析的 JSON
  - API 層的暫時失敗（HTTP 429/5xx）可以重跑那一格一次；JSON 解析失敗算在 variant 頭上
- **b**：finding 總數 ≥ baseline 的一半，擋「什麼都不報就沒有誤報」
- **c**：evidence 引用率 ≥ baseline − 10 個百分點，擋 2×2 實驗那種「把證據從論證裡拿掉」
- **d**：每個標的的 A 類召回（5 次跑加總）≥ baseline − 1
- **e**：probe 標的自己的 AUC ≥ 目前最佳 − 0.05，擋「只靠標的之間的信心水位差撐起合併 AUC」

> **追加（2026-09-24，v00 跑完、v01 之前）**：baseline 自己就有 1 次輸出超過 `max_tokens=8192` 被截斷
> （probe 第 3 次，content 14,789 字元），v00 = 14/15。原本的 a、d 兩條因此對 variant 不對稱，改成：
> - **a**：失敗的跑數 ≤ max(1, baseline 的失敗跑數)。截斷不算 API 暫時失敗，不重跑
> - **d**：A 類召回換算成「每 5 次成功跑」再跟 baseline 比（容許差 1）
> `analyze_round.py` 因此修改，Guard 快照重建。這時還沒有任何 variant 的結果

## 候選攻擊方向（每一輪 propose 時從這裡挑，或提新的）

1. 拿掉 rubric 開頭寫給人看的 5 行（第 3–7 行）
2. 替 confidence 定錨：每一級對應可檢查的條件（例如「能指出觸發的輸入，而且確認附近沒有既有處理」）
3. 拿掉「不要用『可能』『或許』模糊帶過」
4. 拿掉「低於 0.6 直接省略」，讓分數分布完整呈現（門檻交給下游）
5. 告訴模型 confidence 拿來做什麼（≥ 0.7 才貼 inline）——給資訊，不是要求自律
